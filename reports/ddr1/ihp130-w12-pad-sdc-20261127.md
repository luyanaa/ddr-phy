# IHP130 DDR1：W12 DQ pad 与 `ddr1_top` 真实 SDC 收口记录

日期：2026-11-27  
分支：`ddr1-ihp130`  
状态：**两项都只完成到“可复现的物理中间态”，没有达到最终签核条件。**

## 1. 结论先行

### 1.1 W12 DQ pad

按 `xrdriver_w=12 µm` 重画并迭代了 v6c、v10–v16 多版。当前 DRC/LVS 最干净、PEX 最好的一版是 **v6c**：

| 角 | RX rise/fall | TX rise/fall | VOH/VOL | 1.5 ns 判定 |
|---|---:|---:|---:|---|
| TT 1.20/2.50 V 27 °C | 1.196 / 1.378 ns | 1.240 / 1.308 ns | 1.784 / 0.669 V | PASS |
| SS 1.08/2.30 V 125 °C | 1.481 / 1.822 ns | 1.864 / 1.987 ns | 1.594 / 0.650 V | **FAIL** |

- RX rise 已经进 1.5 ns（1.481），RX fall 还差 **0.322 ns**。
- TX rise 还差 **0.364 ns**，TX fall 还差 **0.487 ns**。
- DRC 0、LVS match；PEX 原始元素 X=266、R=6272、C=1793。
- 这一版不是“调参没做够”：把输出管从 300/180 µm 加到 600/360 µm（v11）或 900 µm（v12），schematic 会略好，但 PEX 反而退化到 SS TX 1.984/2.069 ns。原因是 120/180 finger 的栅 bus 和 pad 金属把 PEX 电容从 1793 抬到 2273，驱动变大被寄生吃掉了。
- 把 finger 从 60/45 减到 30/22（v16）也只把 TX fall 从 1.987 拉到 1.971，rise 反而 1.874；没有质变。

**根因判断**：schematic 的 SS TX 已经是 1.30/1.39 ns，PEX 再多出约 **0.56–0.59 ns**。这 0.56 ns 主要来自版图栅 bus/漏端/pad 金属的分布 RC，不是 `XRDRIVER` 的 12 µm 电阻，也不是输出管宽度不够。继续加 W 只会同时加栅电容，进入负反馈。

### 1.2 `ddr1_top` 后端

用真实 DQ pad PEX + QFN48 封装预算替换了占位的 `0.500/0.000`，并把 `sys_clk/ck/ck90` 从“三组异步”改成同源同步族，只保留 `dqs_capture` 异步。结果：

| 指标 | 旧 bring-up | 新 SDC + CTS clustering |
|---|---:|---:|
| 慢角 setup WNS | +5.897 ps | **+75.350 ps**（最终 SDC + CTS clustering） |
| hold WS | +112.18 ps | +316.1 ps（慢角）/ +83.1 ps（快角） |
| max-fanout violations | 104 | **2** |
| unannotated nets | 112 | **52** |
| DRC / LVS / antenna | 0 / 0 / 0 | 0 / 0 / 0 |

- 104 个 max-fanout 里 102 个是 CTS 叶子 buffer，`CTS_SINK_CLUSTERING_SIZE=8` 后消失；剩下 2 个是 **CTS 根 buffer** `clkbuf_0_dqs_capture/X`、`clkbuf_0_sys_clk_regs/X`，fanout 16，限制 8。
- 112 个 unannotated 降到 52 个，全部是 `clkload*` 的 X/Y 输出（CTS 为平衡负载插入的 dummy load），加 1 个 `dqs_tap_ready`。这些网在 SPEF 中没有条目，但都是 clock leaf/dummy，不是数据网。
- 最差 setup 路径仍是 `ck90 -> dm`，中间仍有 CTS 为 **clock latency balancing** 插入的 `delaybuf_*_ck90` 链（64 个 delay buffer）。WNS 变好是因为外部输出延迟从 0.5 ns 提到 2.25 ns，不是因为 delay chain 被拆掉。
- 最终版 setup 余量 **+75.35 ps** 仍小于 0.2 ns 的抗波动目标；只能算“从几乎为零拉到几十 ps”，不能称安全区。

## 2. 这一轮实际改了什么

### 2.1 Pad

- 新增 `sch/pads/ihp130/sstl2_dq_w12_v6.spice`：W12、`XRDRIVER l=0.3u`、`XDRVH 300u/60`、`XDRVL 180u/45`、`XNG 36/72`、RX 比较器加大。
- 新增 `v10`–`v16` 快筛变体，用来验证“输出管更大 / finger 更少 / 预驱动更强”三条方向；结论是 v6 的 60/45 finger + 300/180 µm 输出是最优 PEX 点。
- `generator/ihp130_dq_layout.py` 保留 `IHP_DQ_SCHEMATIC` 覆盖；`DRIVE_NETS` 已扩到 `PG/NG/P_B/N_B/P1/EN`，M3/M4/M5 通道加宽，`PG/NG` 1.8 µm、`P_B/N_B` 1.4 µm。
- v6c 的局部 gate pickup 使用 M2 ±500 nm、3 个横向 via、M3 riser 700 nm；DRC 0、LVS match。full gate M2 rail 版本因 `M2.b` 0.12 µm 间隙已放弃。
- v6c 产物已落到 `results/ihp130/sstl2-dq-w12-v6c/`：GDS、PEX SPICE、`pex_tt_ss.json`、`layout_metadata.json`、渲染 PNG。`results/` 仍被 gitignore。

### 2.2 `ddr1_top`

- 新增 `flow/ddr1_top_realio.sdc`，由 `flow/config.ddr1_top.json` 的 `PNR_SDC_FILE` / `SIGNOFF_SDC_FILE` 指向。
- SDC 关键值：
  - `sys_clk=20 ns`、`ck/ck90=10 ns`，`ck90` 用 2.5/7.5 ns 波形；不再把三者设成异步组。
  - `dqs_capture` 单独异步组；`pad_ck/pad_ck_n` 由 `ck` 生成。
  - DQ/DM/OE：`set_output_delay -clock ck90 -max 2.251 -min 1.915`（2.201/1.865 pad + 0.050 package）。
  - DQS/DQS_OE：`-max 2.651 -min 2.315`，即比 DQ 晚 0.400 ns，作为 DQ 相对 DQS 的提前量。
  - `dq_i`：相对 `dqs_capture` 的输入延迟按 `1.967 - 2.201 - 0.400` 和 `1.615 - 1.865 - 0.400` 算，是负值，代表读数据早于延迟 DQS。
  - CA 仍用 1.5/0.5 ns 的 CK/CA pad 预算，因为 CK pad 没有独立 PEX；这一点在 SDC 注释里明确标成未测。
  - 系统侧 `cmd_* / w_data / w_we / r_data / w_ready` 等补了 0.5/0.0 ns 的 SoC 侧占位预算；`rst`、`dqs_tap_ready` 加注释后 false path。
- `flow/config.ddr1_top.json` 加 `CTS_SINK_CLUSTERING_SIZE=8`、`MAX_FANOUT_CONSTRAINT=8`。

## 3. 没有解决的问题

1. **SS PEX TX/RX ≤ 1.5 ns 没有达到。** 最好 v6c 仍差 0.32–0.49 ns。
2. **168 ps tDS 没有用新 pad GDS 重新证明消除。** 现有 `DQ_OE_PS=1932`、`DQS_CAPTURE_DELAY_PS=600` 仍是旧行为级闭环；新 pad 的 OE 提前量只有 0.400 ns 的 SDC 预算，还没有 pad-in-loop 闭环。
3. **`+5.9 ps` 的 delaybuf 链没有被拆掉。** WNS 提升来自真实输出延迟预算；`ck90` 上仍有 64 个 CTS latency-balance delay buffer，最差路径仍从 `ck90` 起。
4. **2 个 CTS 根 buffer fanout 16 没有清。** 要么接受 `sg13g2_buf_16` 带 16 个 `buf_8` 的 cell-aware 限值，要么在 CTS 后手工把根 buffer 拆成两级；当前两者都没做。
5. **52 个 `clkload*` unannotated 没有清。** 它们是 dummy load，不影响时序，但会让 `report_parasitic_annotation` 计数不为零。
6. **主 `sch/pads/ihp130/sstl2_dq.spice` 仍是 8/0.6 µm 基线**，W12 结果都靠 `IHP_DQ_SCHEMATIC` 覆盖；还没有把最终变体固化为默认原理图。
7. **CK/CA pad 没有独立 PEX**，封装只有 QFN48 最差 pin 的 RLC，板级没有实测；所以现在的 SDC 是“pad PEX + package RLC”级，不是板级签核。

## 4. 下一步建议

1. **Pad 换拓扑，不再加 W。** 当前 0.56 ns 的 PEX 增量说明瓶颈在栅 bus/漏端/pad 金属。优先试：
   - 把 60 finger 输出管拆成 2 个 30-finger bank，各自就近预驱动，缩短栅 bus；
   - 输出 PAD 走线从 1.8 µm 降到满足 20 mA 的最小宽度，减少 pad 金属 C；
   - 预驱动/level shifter 单独做一版，不再和输出管同一行，减少 PEX 交叉。
2. **用 v6c 的 PEX 结果做一次真实的 OE 提前量扫描。** 不靠 SDC 的 0.400 ns 预算，直接在 char deck 里扫 `OE` 到 `DQS` 的相位，确认 168 ps tDS 是否真的被吃掉。
3. **`ddr1_top` 先决定 2 个根 buffer 的取舍。** 推荐做 cell-aware：`sg13g2_buf_16` 允许 fanout 16，把全局 `MAX_FANOUT_CONSTRAINT` 从 8 改成 16，并在报告里写明“这是 cell-aware 限值，不是掩盖数据网违例”。如果坚持 8，就需要 CTS 后手工拆根。
4. **把 `ck90` 的 64 个 latency-balance delay buffer 单独评估。** 它们是为同步 clock family 做 latency balancing 插入的；如果真实板级 CK/CK90 相位由外部保证，应禁止这组 balancing，否则 setup 会被白吃掉约 2.8 ns。
5. **CK/CA pad 补一版独立 PEX**，再把 SDC 里的 1.5/0.5 ns 占位换成实测；否则 `pad_ck` 路径永远不是真实约束。

## 5. 复现入口

```sh
# pad 版图 + DRC/LVS/PEX
IHP_DQ_SCHEMATIC=$PWD/sch/pads/ihp130/sstl2_dq_w12_v6.spice \
  sh sim/ihp130_dq_layout.sh /tmp/w12v6c_layout

# PEX 特征化
/tmp/pkgvenv/bin/python generator/char_ihp130_sstl2.py \
  --cell-netlist /tmp/w12v6c_layout/sstl2_dq_pex.spice \
  --case tt --case ss_low --output /tmp/w12v6c_pex.json

# 全顶硬化
PATH=/nix/var/nix/profiles/default/bin:$PATH TOP=ddr1_top sh flow/run.sh ihp130
```
