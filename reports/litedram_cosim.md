# LiteDRAM controller + `sdram_phy_core` DFI co-simulation (2026-11-27)

**Status: PASS under Verilator 5.032.** The generated LiteDRAM controller
drives the PHY's DFI port, the PHY drives the `sdram_model` through the
generic pad model, and the native LiteDRAM user port is checked for
write/read/masked-write/row-change/turnaround/refresh-retention.

## Configuration

| item | value |
|---|---|
| controller | `sim/litedram_ctrl.v`, generated by `sim/gen_litedram_ctrl.py` |
| PHY | `rtl/sdram_phy_core.sv`, CL=2, `CDC_LATENCY=6` |
| DRAM model | `sim/sdram_model.sv`, 13 row / 9 column / 4 bank, x8 |
| pad | `sim/pad_cell_generic.sv` (behavioral, no package RLC) |
| geometry | `GeomSettings(bankbits=2, rowbits=13, colbits=9)` |
| timing | tRP=2, tRCD=2, tWR=2, tWTR=1, tREFI=780, tRFC=7, tFAW=4, tCCD=1, tRRD=2, tRC=6, tRAS=5 |
| controller settings | `cmd_buffer_buffered=True`, `with_auto_precharge=False`, `with_refresh=False`, `nbankmachines=1` |
| **DFI read latency** | **7** (`PhySettings.read_latency=7`) |

The stock GENSDRPHY value `read_latency = CL+1 = 3` does **not** apply here.
The integrated top adds the read-capture CDC; the measured
`dfi_rddata_en -> dfi_rddata_valid` distance is 7 cycles at CL=2,
`CDC_LATENCY=6`. The extra cycle is the registered `rddata_valid` output
stage in `read_capture_cdc.sv`; the nominal `CL-2+CDC_LATENCY` is 6, the
DFI-visible value is 7. `specs/interface.yaml` and
`specs/timing_contract.yaml` now carry `CL-2+CDC_LATENCY+1`.

## Two issues found and fixed

1. **Write mask was inverted at the wrong time.** The TB originally
   deasserted `wdata_we` right after the native command handshake. LiteDRAM
   forwards `interface_wdata*` to the DFI at the WRITE command, many cycles
   later, so the DFI saw `wrdata_mask=1` and masked the write. The TB now
   holds `wdata`/`wdata_we` stable until the next transaction; the first
   write is `mask=0, we=1` and the masked write is `mask=1, we=0`.
2. **Native `rdata_valid` is not data-valid.** It pulses when the read
   command is accepted. The TB must wait for `dfi_rddata_valid` and sample
   `dfi_rddata`, not the native `rdata` at the command edge. With that fix
   the readback sequence is correct.

## Limits

- Behavioral pad model: no package RLC, no IBIS, no SSN/PDN droop.
- `with_refresh=False` in the controller; the DRAM model's own refresh
  timer is exercised, but controller-issued REF is not.
- Single bank machine, BL=1, one rank, x8.
- Verilator only; Icarus 12 delta-loops on the Migen `always @(*)` blocks
  in this combination and does not advance time.
